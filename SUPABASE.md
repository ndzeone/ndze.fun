# Подключение онлайн-базы (Supabase)

Пока в `assets/js/config.js` пустые ключи, сайт работает в **демо-режиме**: аккаунты, работы и
задания хранятся только в твоём браузере. Чтобы фанаты могли регистрироваться, присылать работы
на оценку и задания на стрим, подключи бесплатную базу Supabase. Это займёт минут 10–15.

---

## 1. Создай проект

1. Зайди на <https://supabase.com> → **Start your project** → войди через GitHub или email.
2. **New project**:
   - **Name** — например, `ndze-site`;
   - **Database Password** — придумай и сохрани (на сайте он не нужен, но пригодится для доступа к базе);
   - **Region** — ближайший к зрителям (например, *Central EU (Frankfurt)*);
   - тариф **Free**.
3. Нажми **Create new project** и подожди 1–2 минуты, пока проект создаётся.

## 2. Создай таблицы и права (schema.sql)

1. В левом меню открой **SQL Editor** → **New query**.
2. Открой файл `supabase/schema.sql` из папки сайта, скопируй **весь** текст и вставь в редактор.
3. Нажми **Run** (или `Ctrl + Enter`). Внизу должно появиться `Success. No rows returned`.

Скрипт создаёт таблицы, правила доступа (Row Level Security), приватное хранилище картинок
`submissions` и делает `dz2ell.official@gmail.com` адресом админа.
Его можно запускать повторно — например, после обновления сайта.

## 3. Настрой вход по email

Открой **Authentication → Sign In / Providers** (в старом интерфейсе — **Authentication → Providers → Email**).

- **Enable Email provider** — должно быть включено.
- **Confirm email** — выбери один из вариантов:
  - **Выключить (проще всего).** Регистрация сразу входит в аккаунт, письма не нужны.
    Важно: в этом режиме зарегистрируйся со своим админским email **сразу после шага 4**,
    до того как выложишь сайт, — иначе кто-то теоретически может занять этот email раньше тебя.
  - **Оставить включённым.** После регистрации человек получает письмо и входит после подтверждения.
    Учти: встроенная почта Supabase отправляет очень мало писем в час и может доставлять их только
    участникам твоей команды Supabase. Для фанатов нужно подключить свою почту:
    **Authentication → Emails → SMTP Settings** (подойдут Resend, Brevo, Mailgun и т.п.).
- **Minimum password length** — поставь `8` (как на сайте).

## 4. Впиши ключи в сайт

1. Открой **Project Settings → API Keys** (или **Project Settings → API** в старом интерфейсе).
2. Скопируй:
   - **Project URL** — вида `https://abcdefghijk.supabase.co` (он же есть в **Project Settings → Data API**
     или под кнопкой **Connect** вверху проекта);
   - ключ **anon public** — длинная строка, начинается с `eyJ...`. Если на странице показаны новые
     ключи (`sb_publishable_...`), открой вкладку **Legacy API Keys** и возьми **anon public** оттуда.
3. Открой `assets/js/config.js` и заполни строку в самом низу:

```js
supabase: {
  url: "https://abcdefghijk.supabase.co",
  anonKey: "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9....",
},
```

4. Сохрани файл и обнови сайт. Жёлтая плашка «Демо-режим» должна исчезнуть.

> **Это безопасно.** Anon-ключ специально сделан публичным: он виден любому, кто откроет сайт,
> и это нормально. Данные защищают правила Row Level Security из `schema.sql` — например,
> чужие работы не видны, а менять оценки может только админ.
>
> **Никогда** не вставляй на сайт и не выкладывай в GitHub ключ **service_role** (secret key):
> он обходит все правила и даёт полный доступ к базе.

## 5. Стань админом

1. Открой сайт → **Войти** → **Регистрация**.
2. Зарегистрируйся с email **dz2ell.official@gmail.com** (ник — любой свободный).
3. Если подтверждение email включено — подтверди письмо и войди.
4. После входа появится пункт **Админ**: статистика, очереди работ и заданий, оценки.

Роль admin выдаётся только **подтверждённому** email из списка админов.

### Как добавить ещё одного админа

В **SQL Editor** выполни (email — маленькими буквами):

```sql
insert into public.admin_emails (email) values ('drug@example.com');
```

Если человек уже зарегистрирован, роль обновится сразу — ему достаточно перезайти на сайт.
Убрать админа:

```sql
delete from public.admin_emails where email = 'drug@example.com';
```

Список админов — именно таблица `admin_emails`; менять роль руками в `profiles` не нужно
(она пересчитается при следующем изменении списка).

> **Если «Confirm email» выключен**, Supabase не проверяет, что email действительно твой — ни при
> регистрации, ни при смене email в аккаунте. Поэтому админский адрес должен быть **уже занят**
> настоящим админом: сначала человек регистрируется, и только потом его email добавляется в
> `admin_emails`. Иначе кто-то может успеть зарегистрироваться (или сменить email) на этот адрес первым.

## 6. Адрес сайта и ссылки возврата

Открой **Authentication → URL Configuration**:

- **Site URL** — `https://ndze.fun`
- **Redirect URLs** — нажми **Add URL** и добавь по одной:
  - `https://ndze.fun/**`
  - `http://ndze.fun/**`
  - `http://localhost:8000/**` — чтобы вход работал и при запуске через `start.bat`.

Это нужно для ссылки подтверждения email и для входа через Discord: после него человек
вернётся на ту страницу, откуда входил, и сразу окажется в аккаунте. Если адреса нет в списке,
Supabase вернёт человека на **Site URL** (главную).

## 7. Вход через Discord

Кнопка «Войти через Discord» в окне входа заработает после этих шагов (минут 5).

**В Discord:**

1. Открой <https://discord.com/developers/applications> → **New Application** → имя, например `ndze site` → **Create**.
2. Слева **OAuth2**. Скопируй **Client ID**. Нажми **Reset Secret** → скопируй **Client Secret**
   (он показывается один раз; никуда его не выкладывай и не вставляй в файлы сайта).

**В Supabase:**

3. **Authentication → Sign In / Providers** → **Discord** → включи **Enable Sign in with Discord**.
4. Вставь **Client ID** и **Client Secret** из Discord.
5. Там же скопируй **Callback URL (for OAuth)** — он вида `https://<твой-проект>.supabase.co/auth/v1/callback`.
   Нажми **Save**.

**Снова в Discord:**

6. **OAuth2 → Redirects** → **Add Redirect** → вставь Callback URL из шага 5 → **Save Changes**.

**И проверь шаг 6** (Site URL `https://ndze.fun` и Redirect URLs) — без него Discord вернёт человека не туда.

Как это работает:

- Ник берётся из имени в Discord: лишние символы заменяются на `_`, длина — до 16 символов.
  Если такой ник уже занят, к нему добавляются 4 цифры (`Pauk` → `Pauk4821`). Поменять ник потом
  можно только тебе — в **Table Editor → profiles**.
- Если в Discord подтверждён тот же email, что и у аккаунта на сайте, Supabase входит в **этот же**
  аккаунт, а не создаёт новый.
- Роль admin через Discord выдаётся так же: email из `admin_emails`, и он подтверждён (у Discord
  подтверждённый email считается подтверждённым и в Supabase).

## 8. Проверка базы (автотест)

В папке сайта есть `tests/db-check.html` — он сам проверяет, что правила доступа работают:
гость не видит чужие работы, пользователь не может поставить себе оценку или стать админом,
нельзя проголосовать дважды, чужие картинки не открываются и т.д. (несколько десятков проверок).
Папка `tests/` на хостинг не выкладывается.

1. Впиши ключи в `config.js` (шаг 4) и запусти `schema.sql` (шаг 2).
2. **На время проверки** выключи **Authentication → Sign In / Providers → Email → Confirm email** —
   тестовые аккаунты должны входить без письма. После проверки включи обратно, если он был включён.
3. Запусти `start.bat` и открой <http://localhost:8000/tests/db-check.html>.
4. По желанию впиши email и пароль админа — тогда проверятся и админские действия
   (оценка, статус «Идеал», удаление чужого задания). Пароль никуда не сохраняется.
   Ключ **service_role** проверке не нужен — никогда не вставляй его никуда.
5. Нажми **Запустить проверку** и подожди до минуты. Зелёные строки PASS — всё хорошо,
   красные FAIL — в колонке «Подробности» написано, что не так.

После проверки:

- тестовые работы и задания проверка удаляет сама;
- тестовые аккаунты (`dbcheck+…@example.com`) удали вручную: **Authentication → Users** →
  поиск `dbcheck` → **⋯** → **Delete user** (их профили удалятся вместе с ними).

Если Supabase ругается на email `@example.com`, впиши в поле «Шаблон email» свой адрес с плюсом,
например `ndze+dbcheck-{id}@gmail.com` — при выключенном Confirm email писем всё равно не будет.

## Где смотреть данные

- **Table Editor** — таблицы `profiles`, `submissions`, `tasks` и т.д.
- **Storage → submissions** — загруженные картинки (папка = id автора / id работы).
- **Authentication → Users** — аккаунты; там же можно удалить пользователя
  (его профиль, работы, комментарии и голоса удалятся вместе с ним).

На бесплатном тарифе проект **засыпает после недели без посещений** — тогда зайди в панель
Supabase и нажми **Restore project**.

## Если что-то не работает

| Что видно | Что сделать |
|---|---|
| «Нет связи с сервером» на всех страницах | Проверь `url` в `config.js` (без опечаток, `https://`), что проект не на паузе, и что сайт открыт через `start.bat`, а не двойным кликом. |
| «Недостаточно прав» или пустые списки сразу после подключения | `schema.sql` не запускался или упал с ошибкой. Запусти его ещё раз целиком и посмотри сообщение внизу SQL Editor. |
| «Мы отправили письмо на email», но письма нет | Проверь «Спам». Встроенная почта Supabase шлёт мало писем — подключи SMTP (шаг 3) или выключи **Confirm email**. |
| После регистрации нет пункта «Админ» | Email должен совпадать с записью в `admin_emails` и быть подтверждённым. Выйди и войди снова. Проверить: `select * from public.profiles;` в SQL Editor. |
| «Этот ник уже занят» | Ники уникальны без учёта регистра (`Pauk` и `pauk` — один ник). Выбери другой. |
| Ссылка из письма открывает не тот сайт | Поправь **Site URL** и **Redirect URLs** (шаг 6). |
| Discord: «Invalid OAuth2 redirect_uri» | В Discord → **OAuth2 → Redirects** должен быть ровно Callback URL из Supabase (шаг 7.5). |
| После Discord попадаю на главную, а не туда, откуда входил | Добавь адрес сайта со `/**` в **Redirect URLs** (шаг 6). |
| «Вход через Discord не удался: …» | Провайдер Discord выключен или неверный Client Secret (шаг 7). Ещё бывает, если у аккаунта Discord нет email. |
| «Вход через Discord заработает после подключения онлайн-базы» | Сайт в демо-режиме — впиши ключи в `config.js` (шаг 4). |
| Картинки не показываются | Бакет `submissions` должен существовать и быть **приватным** (Storage). Если его нет — снова запусти `schema.sql`. Ссылки на картинки временные (1 час): просто обнови страницу. |
| «Слишком много запросов» | Сработал лимит Supabase на регистрации/входы. Подожди несколько минут. |
